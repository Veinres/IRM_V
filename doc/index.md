## Overview of Scripts, Functions and Folders

This sections attempts to give an overview of the most relevant scripts and functions in the order they would typically be called (or are called by the code).

![Overview of code components](img/components.png "An overview of the IRM code components")

### Species / Reactions

Species properties and reaction sets are stored in matlab structures (struct), which are generated by a couple of functions which are located in the [species\_reactions directory](../species_reactions):

- \<irm-root\>
	- species\_reactions
		- create\_Rea\_new.m
		- create\_reactions\_new.m
		- create\_Spe\_new.m
		- create\_species\_new.m
		- Rea\_\<gas\>\<target\>.mat
		- Spe\_\<gas\>\<target\>.mat
		- ...

The functions **create_species_new** and **create_reactions_new** contain species and their properties and reaction sets respectively. When called they produce a list of species, respectively, reactions relevant for a given combination of working gas and target material.The functions **create_Spe_new** and **create_Rea_new** are then in turn used to convert these list into the matlab structure (struct) that is then used by the simulation. To (re-)generate the species and/or reactions structure, the latter two functions can be called directly. Internally they will call the former two functions to generate the required species or reactions list.
Typically the naming scheme for the generated .mat files is Spe or Rea (for species or reactions, respectively) followed by an underscore and the element symbol of the working gas and target material.

*Note:* This part of the code base is currently in a refactor-process. The associated functionality will be regrouped in the [+material](../%2Bmaterial) matlab package.

### Pre-Cal

The IRM depends on material/species properties. These properties can be a function of temperature, an in the case of sputter or secondary electron yields, ion energy (which is approximated by the discharge voltage).
In order to avoid evaluating these functions at each time step, these functions are evaluated for a given energy range and then interpolated (using the previous neighbour method) during the integration.
The values of said functions are stored in in matrices in their respective .mat files. 
When a new material is introduced  or changes are made to an existing material, these matrices have to be recomputed and the .mat files regenerated.
Functions associated with this procedure are located in the [pre-cal directory](../pre-cal):

- \<irm-root\>
	- pre-cal
		- Ec
			- create\_Ec.m
			- Ec\_\<gas\>\<target\>.mat
			- ...
		- Secondary\_e\_yield
			- create\_Gamma.m
			- gamma\_\<gas\>\<target\>.mat
			- ...
		- Sputter\_yield
			- create\_Yield.m
			- Yield\_\<gas\>\<target\>.mat
			- ...

Each type of pre-calculated property has its own subdirectory, which contains a function for generating the .mat files as well as the generated .mat files.

- **create_Ec.m** : Pre-calculate the effective cost of ionization (as a function of effective temperature) for all species.
- **create_Gamma.m** : Pre-calculate the secondary electron yield (as a function of discharge voltage) for all ion species.
- **create_Yield.m** : Pre-calculate the sputter yield (as a function of discharge voltage) for all ion species.

The functions serve a dual purpose. They generate the pre-cal matrices, but they also hold the functions which will be evaluated to this prupose.
To produce the pre-cal matrices, the pre-cal functions require a species structure (struct) as input.

*Note:* This part of the code base is currently in a refactor-process. The associated functionality will be regrouped in the [+material](../%2Bmaterial) matlab package.

### Parameters

Parameters which depend not only on the type of discharge (i.e working gas and target material) but also on the specific discharge itself go into the *Para.mat* file loacted in the [parameters directory](../parameters). The parameters for a new discharge can be edited directly in the **create_Para.m** file by adding a new case to the switch/case statement.

The parameters *f*, *r* and *beta* don't have to be edited, since they will be changed anyway during the fitting procedure. The parameters *F_Teh* and *U_htc* aren't usually changed either and the parameter *deg_poi* is only relevant for reactive sputtering.
This leaves only the Ionization Region (IR) dimensions (*r1*, *r2*, *z1* and *z2*) to be adapted to each discharge.

### Discharge

The experimental input required by the Ionization Region Model (IRM) is stored in matlab structure (struct) called *disch*. This structure has to contain the following fields:

- V : The discharge voltage waveform in volt (either negative or possitive - doesn't matter)
- I : The discharge current waveform in ampere
- T : The time values for V and I in microseconds
- dt : The distance between time steps (also in microseconds)

Additionally, the measured Ionized Flux Fraction (IFF) and pressure can be specified here as well:

- F\_flux : The measured ionized flux fraction
- p : The process pressure in pascal

Typically these structures are saved in a .mat file in a subdirectory of the [discharge directory](../discharge). named after the discharge itself. E.g. the experimental data for a previously performed experiment with a copper target and using argon as working gas is stored in 'discharge/ArCu\_HiPSTER\_40us\_0.5Pa\_130A/disch.mat'.

### Simulation

Most functions or scripts relevant for running the simulation itself are located in the IRM root directory.
The most important are (in the order they are usually called):

- panel\_Pfit\_fct.m
- panel\_mode\_single\_run\_Pfit\_modified\_fct.m (some of these desperately need a name change 😉)
- create\_Input\_fct.m
- ODEfile.m
- extract.m
- analyse\_fct\_\<gas\>\<target\>.m
- calculate\_fom.m

The *panel_Pfit_fct* function, launches a grid scan over the fitting parameters *f*, *beta* and *r*, i.e. this function will run a simulation for each combination of these parameters in the specified parameter range. The individual simulation runs are performed in the *panel_mode_single_run_Pfit_modified_fct* function. First it generates the initial conditions for the system of ordinary differential equations (ODE), which is done in the *create_Input_fct* function. Then it proceeds to integrate the ODE using the matlab built-in *ode15s* function. The integrand, which is evaluated at each internal time-step and contains the relevant physics, is provided via the *ODEfile* function. Once the integration is finished, the state of the system is reconstructed at the predifined timesteps using the *extract* function, the output of which can then be analyse using one of the variations of the *analyse_fct* function. Once all individual simulation runs have been performed, the *panel_Pfit_fct* function picks out the set of fitting parameters that reproduced the discharge current (and, if necessary the ionized flux fraction) the best and rerun it. The quality of the fit is determined by the *calculate_fom* function (FOM stands for figure of merit). 

### Results

The output of each simulation run is saved in a user-specified subdirectory of the [results directory](../results).
This directory is not synchronized with the remote repository, since the amount of data can grow quite rapidly. It is therefore also recommended to periodically remove results that aren't needed anymore.

### Plotting

The [plotting directory](../potting) contains routines for visualizing the results of a single simulation run. Typically these results are only plotted for the run achieving the best fit.
Some of these functions may be adapted specifically for a single type of discharge and might therefore need editing to use them for another combination of target material and working gas.

### Remarks

That's basically all there is to it. There are directories, scripts and functions that aren't mentioned above. That either means that they are non-essential, only fullfill a minor role or are even deprecated.

#### Non-essential components

Some of the non-essential scripts wroth mentioning nevertheless are the various scripts present in the IRM root directory. The purpose of these scripts is running large batches of jobs (e.g. for multiple different discharges). The simplest one is called *multirun.m*, which just contains multiple calls to *panel_Pfit_fct*. If that becomes unwieldy, *run_IRM.m* can be adapted to run a large collection of discharges. It handles naming and setting up parameters in a semi-automated fashion and displays some statistics at the end of the job. 

#### Refactor in progress

Parts of this code base are a bit messy at the moment. This is, to some part, due to different versions of the code having been merged quite recently.
In an effort to clean the code base up, some components of the IRM matlab code are currently being refactored or planned to be refactored in the near future. To begin with, the old components will however still be kept and the refactor is done in a way to guarantee interoperability.

Once these changes are tested and pushed to the repository, this overview will be adapted accordingly.
